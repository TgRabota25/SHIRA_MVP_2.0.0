# SHIRA MVP 2.0 — этикетки и видеоархив

## Установка на чистую систему

Целевая поставка: Windows 10/11 x64, локальный диск, обычная пользовательская учётная запись. Интернет для установки и распознавания не требуется. Рекомендуется минимум 8 ГБ RAM и свободное место с запасом для видео, кадров и базы; поддерживается экономичный профиль. GPU не используется. Это рабочий MVP, а не сертифицированный отказоустойчивый промышленный комплекс.

1. Закройте старую SHIRA. Через её интерфейс сделайте резервную копию базы.
2. Распакуйте весь ZIP, например в `C:\SHIRA_MVP_2`. Не запускайте команды прямо из архива. Не удаляйте эту папку после установки.
3. Запустите `01_INSTALL.cmd`. Разрешите установку Microsoft Visual C++, если Windows запросит права администратора. Не отключайте защиту Windows и не игнорируйте предупреждения об изменённых контрольных суммах.
4. Установщик проверит SHA-256, поставит Python и зависимости из архива, проверит OCR/QR, Tk и Windows-функции. `SUCCESS` выводится после этих проверок. После установки откроется приложение.
5. В дальнейшем используйте новый ярлык **SHIRA MVP** или `02_START.cmd`. Старую закреплённую иконку на панели задач открепите; запустите новый ярлык и закрепите заново.
6. Для проверки установки запустите `03_DIAGNOSTICS.cmd`; для тестов — `04_TESTS.cmd`. Диагностика заменяет содержимое буфера обмена контрольным файлом.

Комплект содержит установщики Python 3.13.16 x64 и VC++, локальный Tesseract 5.5.0, английские и русские модели, все Windows-wheel зависимости с хешами, приложение и исходники. `vendor/tesseract-original-installer.exe` сохранён для происхождения/лицензий; отдельно запускать его не нужно: рабочие бинарники находятся в `app/tesseract`.

## QR-якорный OCR

Функция называется **QR-якорный OCR: распознавание трек-номера рядом с QR по шаблону**. QR используется как ориентир области этикетки. Его содержимое не считается автоматически искомым номером.

Пример нового шаблона: `81604409-0321-5`, регулярное выражение `(?<!\d)\d{8}\s*[-–—]\s*\d{4}\s*[-–—]\s*\d(?!\d)`.

- Сначала декодируются QR / штрихкоды и локализуются области кодов.
- OCR проверяет область вокруг QR; при необходимости — полный кадр; пробует повороты 0/90/180/270 градусов и контрастирование.
- Даже если QR даёт другой подходящий номер, текст проверяется на выбранных OCR-кадрах. Несколько разных номеров в короткой сессии переводят результат в ручную проверку.
- Если QR не содержит трека, номер может быть извлечён из печатного текста рядом.
- Один OCR-кадр — только кандидат. Совпадение строгого шаблона на двух разных выбранных кадрах — согласованный результат, но не математическая гарантия истинности.
- При нескольких этикетках рядом геометрическая принадлежность текста конкретному QR не гарантируется. Конфликт в короткой сессии требует оператора; длинная хранит все найденные наблюдения.

Включены строгие Ozon `ii` + 11 цифр, прежний Ozon `10-4-1..3`, Яндекс-груз `11-1..3`, новый `8-4-1`; прежние мягкие варианты сохранены как кандидаты для проверки. Голые 11 цифр допускаются только из QR и остаются сомнительными, не из произвольного текста. Мягкие совпадения никогда автоматически не подтверждаются. В настройках можно добавлять собственные шаблоны: `name`, `market`, `regex`; необязательное `source: "qr"` ограничивает источник. Пользовательские regex должны быть доверенными; время обработки ограничено на уровне процесса, но сложное выражение способно привести к тайм-ауту.

## Короткая сессия

1. Выберите **Короткая** и профиль, либо нажмите **Авто**.
2. Добавьте файлы или папку; нажмите **Обработать очередь**.
3. Видео проверяется равномерной выборкой по всей длительности. QR проверяется на всех выбранных кадрах, OCR — на ограниченном количестве равномерно распределённых кадров.
4. Двойной щелчок по строке открывает проверку: кадр, кандидаты, номер, маркетплейс, исходный путь и история. Уточните номер и нажмите **Подтвердить номер**.
5. Жёлтые строки требуют проверки; красные — ошибка; оранжевые — пропуски; зелёные — распознано; синие — подтверждено оператором.

Файлы с одинаковым именем в разных папках не объединяются. Идентификатор учитывает путь, размер, время изменения, начало и конец файла. Это не полный криптографический хеш всего длинного видео. Перемещённый файл считается новым источником.

## Длительная сессия

1. Выберите **Длительная**. Откройте **Настройки / шаблоны** до добавления видео.
2. Установите шаг QR-поиска. По умолчанию 1 секунда. OCR по умолчанию выполняется на каждом третьем выбранном кадре; для этикеток, где нужный номер только в тексте рядом с QR, рекомендуется `N = 1` и подберите шаг по времени видимости этикетки.
3. Добавьте длинное видео, включая записи больше восьми часов, и запустите очередь.
4. Обработка разбивается на интервалы 30–60 секунд исходного видео, каждый в отдельном процессе. В память загружается кадр, а не весь файл. После интервала попадания и позиция сохраняются одной транзакцией.
5. Откройте **Индекс этикеток** или дважды щёлкните длинное видео. Введите номер / часть номера. Таблица показывает номер, источник, файл и таймкод.
6. Двойной щелчок по найденной этикетке / **Кадр по таймкоду** извлекает кадр из исходного видео. **Открыть видео** открывает системный плеер с начала; автоматический переход плеера к таймкоду не реализован.
7. **Сводка** показывает первые / последние наблюдения и количество кадров по треку и видео. Это не подсчёт посылок и не точные границы появления этикетки.
8. При остановке выберите файл и нажмите **Повторить выбранные**, затем **Обработать очередь**: незавершённое видео продолжается с сохранённого интервала. **Сначала / переиндексировать** очищает текущие попадания выбранных файлов после предупреждения.

**Важные ограничения длинного режима:** выбранные кадры — дискретная выборка. Этикетка между ними может быть пропущена. Для восьмичасового 30 fps видео проверка каждого кадра не выполняется. OCR с меньшим шагом повышает покрытие, но увеличивает время обработки; скорость на ваших реальных записях не измерена. На файлах с неверной длительностью / повреждённым индексом или нестандартным кодеком возможны ошибки. Длинные записи с VFR требуют проверки таймкодов; время основано на метаданных и позиции OpenCV. Проверен искусственный девятичасовой контейнер с редкими кадрами, но не девять часов непрерывной производственной нагрузки.

## Копирование и работа с файлами

- **Ctrl+C** в таблице копирует выделенные строки в табличном текстовом виде; в полях — выделенный текст. Правый клик открывает контекстные команды.
- **Ctrl+A** выделяет строки текущей страницы. **Ctrl+клик** — несколько строк; **Shift+клик** — диапазон. Межстраничное выделение не сохраняется; страница ограничена 200 строками.
- **Повторить выбранные** возвращает выделенные файлы в очередь. Если незавершённая длинная сессия — продолжает; завершённая переиндексируется. Для изменения параметров уже добавленного задания пока требуется добавить источник в новой базе / режиме; сохранённые параметры не заменяются автоматически.
- Щелчок по заголовку меняет направление сортировки по всей отфильтрованной базе. Поддерживаются все столбцы основной таблицы и столбцы индекса.
- Путь доступен в основной таблице, нижнем поле и окне проверки. Двойной щелчок по столбцу пути / **К файлу** открывает Проводник с выделенным исходником.
- **Копировать путь** копирует текст; **Копировать файл** кладёт Windows-список файлов в системный буфер. Вставка вложения Ctrl+V зависит от почтового клиента; если он не принимает файлы, используйте «Прикрепить файл» и вставьте путь. Программа сама не отправляет почту и не копирует содержимое большого видео в оперативную память.
- Иконка `icon-3.jpg` преобразована в многоразмерный `app/icon.ico` и PNG; назначена основному окну, дочерним окнам и ярлыку. Системное отображение значка панели задач зависит от кэша Windows и способа запуска; используйте новый ярлык.

## Автовыбор профиля

**Авто** использует доступную RAM и число физических CPU-ядер: weak при ограниченных ресурсах, balanced от 5 ГБ доступной RAM и четырёх ядер, powerful от 12 ГБ и восьми ядер. Это консервативная эвристика, не тест скорости. Кнопка находится непосредственно рядом с выбором профиля. Параметры копируются в задание при добавлении; работающие и ранее добавленные задания не меняются. Число одновременно запущенных заданий при старте очереди определяется текущим профилем (1/2/4).

## Отказоустойчивость

- Отдельные процессы для декодирования и распознавания; тайм-аут OCR и всего интервала; остановка дерева дочерних процессов.
- На Windows используется Job Object с kill-on-close; при недоступности — резервная остановка через psutil с записью предупреждения.
- Один активный экземпляр на каталог данных. SQLite с WAL и synchronous=FULL; транзакционное сохранение результатов/позиции, без сетевой общей базы.
- Повторная попытка проблемного интервала; после двух неудач известный интервал длинного видео отмечается как пропуск, а не как успешно обработанный. В конце появляется **Есть пропуски**. История пропусков доступна отдельно.
- Изменённый / исчезнувший источник — ошибка целого задания, не тысячи пропусков. Ошибка одного файла не должна останавливать остальные.
- После аварийного закрытия running-задачи возвращаются в очередь при следующем запуске; незавершённый интервал повторяется. Для Ctrl+Stop / штатного закрытия состояние сохраняется; при физическом отказе диска сохранность не гарантируется.
- Ограничены GUI-очередь, отображаемые строки и журнал; лог ротируется. Экспорт выполняется фоново и потоково, Excel разбивается по лимиту листа. Формульные строки экранируются.
- Проверка свободного места: при менее 256 МБ обработка останавливается; при менее 512 МБ кадры-доказательства не сохраняются. Освободите диск, возобновите или переиндексируйте. Сам видеоисточник не изменяется.
- SHA-256 компонентов и фиксированные wheel-зависимости. Контрольные суммы выявляют случайное изменение, но не заменяют доверенную цифровую подпись издателя.

## База, экспорт, обновление

Данные по умолчанию: `%LOCALAPPDATA%\SHIRA_MVP`.

- `index-v2.sqlite3` — новая база; `settings-v2.json` — настройки; `evidence-v2` — кадры; `logs` — ротируемые журналы.
- `installation-v2.log`, `diagnostics-v2.json`, `startup-error.txt` — диагностика.
- Старая база не удаляется и не мигрирует молча. **Настройки → Импортировать результаты предыдущего MVP** читает v1-базу с таблицей `jobs` в read-only. Несовместимая `checked_videos.db` отклоняется. Результаты импортируются, но история/кандидаты v1 не переносятся; файл импорта сохраняется неизменным.
- Сделайте **Бэкап БД** до переиндексации / обновления. Для восстановления закройте все процессы SHIRA; сохраните копию каталога данных; замените `index-v2.sqlite3` из бэкапа и удалите оставшиеся `index-v2.sqlite3-wal`/`-shm` только при полностью закрытом приложении. Кадры хранятся отдельно и в SQLite-бэкап не входят.
- **Экспорт**: CSV / XLSX. Короткая сессия — итоговый номер с учётом ручного исправления; длинная — наблюдения с таймкодами. Полный экспорт без GUI-лимита 200 строк.
- Не открывайте рабочую базу из сетевой папки, не синхронизируйте живые SQLite-файлы через облачную папку. Периодически копируйте бэкап и кадры на другой диск.

## Пакетный запуск

Из командной строки в папке приложения:

```bat
05_BATCH.cmd "D:\Видео" --recursive --mode short --profile weak --export "D:\result.xlsx"
05_BATCH.cmd "D:\archive.mp4" --mode long --profile balanced --step 0.5 --ocr-every 1
05_BATCH.cmd --search "81604409-0321-5"
```

GUI и CLI одновременно с одной базой не запускаются. Команда поиска показывает до 200 совпадений; полный результат доступен экспортом. Для независимого каталога задайте `SHIRA_DATA_DIR`. CLI обрабатывает все ожидающие задания в выбранной базе, не только файлы из текущей команды.

## Проверки и ограничения поставки

В `docs` находятся результаты 66 автоматических тестов, GUI-проверки, CLI, диагностики и проверки Windows-wheel. Реальный OCR работал на Tesseract 5.3.0 Linux, бинарники поставки Windows — 5.5.0. Пройдены служебный QR + текст, поворот, короткое видео с разными QR, интервальное продолжение, испорченный файл, тайм-аут, контрольная точка после восьми часов, SQL-сортировка, копирование текста, экспорт и импорт.

**Чистая Windows и реальные восьмичасовые записи здесь не прогонялись.** Windows-установщик, системная иконка панели задач, CF_HDROP и Job Object требуют локального подтверждения. Установщик проверяет важные Windows-вызовы на машине пользователя, но это не заменяет независимую приёмку. Тестовые этикетки — явно искусственные; показатели точности/производительности по ним не заявляются. Невозможно гарантировать распознавание размытых / слишком маленьких этикеток или отсутствие всех ошибок.

Это локальное CPU-приложение, без камеры, EasyOCR/PyTorch/GPU, серверной многопользовательской работы, цифровой подписи EXE и гарантированной поддержки Linux/macOS. Исходный проект сохранён в `original` для сравнения; запускается новое модульное ядро в `app`.
